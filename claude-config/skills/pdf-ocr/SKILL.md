# pdf-ocr — распознавание PDF средствами Claude Code

Главный принцип: **сначала брать то, что в PDF уже есть, и только потом читать глазами.**
Текстовый слой точен на 100 %, чтение картинки — нет. Поэтому каждая страница сначала
проходит сортировку, а в итоговом отчёте всегда видно, какие страницы распознаны глазами
и требуют сверки с оригиналом.

## Шаг 1. Сортировка страниц

```bash
python3 ~/.claude/skills/pdf-ocr/scripts/prepare.py "<файл.pdf>"                 # весь файл
python3 ~/.claude/skills/pdf-ocr/scripts/prepare.py "<файл.pdf>" --pages 2       # «страница 2»
python3 ~/.claude/skills/pdf-ocr/scripts/prepare.py "<файл.pdf>" --pages 3-5,8   # несколько
python3 ~/.claude/skills/pdf-ocr/scripts/prepare.py "<файл.pdf>" --pages 10-     # с 10-й до конца
```

Скрипт кладёт результат в `./pdf-ocr/<имя файла>/` и печатает сводку. Виды страниц:

| Вид | Что значит | Откуда брать содержимое |
|---|---|---|
| `text` | нормальный текстовый слой (испорченная кодировка CP1251 из AutoCAD исправлена) | `page-NNN.txt` — **только отсюда** |
| `scan` | скан, фото, «печать в PDF» с текстом в кривых, испорченный слой | фрагменты `page-NNN-tK.png` — читать глазами |

`--render-all` — рендерить и страницы с текстовым слоем. Нужен, когда важно то, чего в слое
нет: зачёркивания, печати, подписи, рукописные пометки, цветные выделения.

Нужен `poppler-utils` (`pdftotext`, `pdftoppm`, `pdfimages`). Если его нет — сказать
пользователю: `sudo apt install poppler-utils`.

## Шаг 2. Страницы `text` — без пересказа

- Содержимое берётся из `page-NNN.txt` **программно** (Python: разбор строк по колонкам,
  регулярные выражения) или дословным копированием. Не перепечатывать большие таблицы «от себя»:
  на перепечатке модель ошибается так же, как на чтении картинки.
- Ничего не исправлять: опечатки исходника, латиница вместо кириллицы, странные единицы
  остаются как в PDF.
- Колонки в `-layout` выровнены пробелами. Перенос строк — по общему правилу ниже.

## Шаг 3. Страницы `scan` — чтение глазами по правилам

Открыть каждый фрагмент `page-NNN-tK.png` инструментом Read. Соседние фрагменты перекрываются
на ~100 px — одна-две строки таблицы видны на обоих. Такую строку взять один раз.

Правила переписывания — без исключений:
1. **Дословно.** Не исправлять опечатки, не «улучшать» формулировки, не переводить единицы.
2. **Кириллица или латиница.** На картинке `А`/`A`, `С`/`C`, `Х`/`X`, `Н`/`H`, `Р`/`P` часто
   неотличимы. Порядок такой:
   - русские слова и русские единицы (`А`, `В`, `кВт`, `мм`, `шт.`) — кириллицей;
   - латинские коды, марки и единицы в латинском окружении (`S 201-C`, `ML1-100W`, `AC24V`,
     `16A`, `220V`) — латиницей;
   - размеры `20х60х2000` — как в документе; если не видно, кириллическая `х`;
   - в отчёт выносить только места, где от буквы зависит смысл: артикул, марка, код позиции.
3. **Не угадывать.** Нечитаемое — `[неразборчиво]`, частично читаемое — `1095[?]2`. Текст,
   частично закрытый печатью или штампом, — читаемая часть плюс `[?]`; сначала посмотреть
   увеличенный фрагмент (`--zoom`, см. ниже). Пустую ячейку оставлять пустой, не переносить
   в неё значение из соседней строки.
4. **Пометки.** Зачёркнутое — `~~текст~~`, печать — `[печать: текст]`, подпись — `[подпись]`,
   рукописное — `[от руки: текст]`, логотип — `[логотип]`, QR-код — `[QR-код]`. Основную
   надпись (штамп листа), пустые строки бланка и рамку не переносить, если не попросили.
5. **Дефис.** Чертёжные шрифты рисуют дефис длинным (`1—полюсный`). В словах и кодах писать
   обычный дефис `-`; тире оставлять только там, где это действительно тире в тексте.
6. **Структура.** Таблица остаётся таблицей: те же колонки, тот же порядок строк, объединённые
   ячейки — повтором значения с пометкой в отчёте.

### Перенесённые строки (сканы и текстовый слой одинаково)

В спецификациях и счетах одна позиция часто занимает две физические строки бланка.
- **По умолчанию** — переносить строки как в документе, по одной на строку бланка.
- **Склеивать** продолжение с предыдущей строкой, только если пользователю нужна «одна позиция —
  одна строка» (для Excel под расчёт или сравнение) **и** у строки-продолжения нет своего
  номера позиции и своего количества. Если количество есть — это отдельная позиция, не клеить.
- Что склеено — перечислить в отчёте.

### Контрольная проверка (обязательна для сканов с цифрами)

После первого прочтения страницы:
1. Сверить **только цифры**: количества, суммы, цены, даты, номера документов, ИНН, счета,
   артикулы. Не перечитывать те же пиксели: колонку с цифрами открыть увеличенной —
   ```bash
   python3 ~/.claude/skills/pdf-ocr/scripts/prepare.py "<файл.pdf>" --zoom <стр> <x> <y> <w> <h>
   ```
   `x y w h` — доли листа от 0 до 1 (например, правая треть верхней половины:
   `0.66 0 0.34 0.5`), разрешение по умолчанию 400 dpi. Обязательно — для цифр под печатью
   или штампом: модели чаще всего теряют цифру именно там.
2. Если в документе есть итоги («Итого», «Всего», «В том числе НДС») — пересчитать в Python
   сумму строк и сравнить с итогом. Не сходится — найти строку-виновника по картинке.
   Если итог в документе ошибочен сам по себе — оставить как есть и написать об этом.
3. Если итогов нет (письмо, акт, реквизиты) — сверить значения, которые встречаются в
   документе несколько раз: сумма цифрами и прописью, ИНН в шапке и в подписи, номер
   договора. Расхождение — перечитать увеличенным.
4. Посчитать строки таблицы на картинке и в результате — должно совпасть.

## Шаг 4. Результат

Формат — тот, что попросил пользователь. По умолчанию Markdown рядом с промежуточными
файлами: `./pdf-ocr/<имя файла>/result.md`.

Результат — расшифровка документа, а не текст от себя. Не прогонять его через редактуру,
«очеловечивание» и проверку стиля, даже если на сервере есть такие правила для исходящих
текстов: любая правка нарушит дословность.

- **Excel:** если на сервере есть `/opt/openpyxl_safe` — подключить его до `openpyxl`
  (`sys.path.insert(0, "/opt/openpyxl_safe"); import openpyxl_safe`). Числа — числами,
  артикулы и коды — текстом (иначе Excel съест ведущие нули и превратит `1-2` в дату).
- **CSV:** UTF-8 с BOM (`utf-8-sig`), разделитель `;` — так его без вопросов откроет Excel.
- **Word:** `python-docx`, таблицы — таблицами.

## Шаг 5. Отчёт пользователю — всегда

В конце ответа — короткая сводка, без неё работа не сдана:

```
Страниц: 12. Из текстового слоя (точно): 1–9. Распознано глазами: 10–12 — сверьте с оригиналом.
Неразборчиво: стр. 11 — 2 места (строка 7, колонка «Кол.»; печать).
Итоги пересчитаны: стр. 12 — сходится.
Сомнения в буквах: стр. 10 — марка «HH100» (латиница или кириллица — неразличимо).
```

## Большие документы

- Сканов больше ~20 страниц — предупредить: чтение картинок расходует лимиты подписки
  заметно быстрее обычной переписки. Предложить взять только нужные страницы (`--pages`).
- Длинный скан можно разделить между субагентами (Agent tool) по диапазонам страниц: каждому —
  те же правила шагов 3–4 и путь к своим фрагментам. Сборку и итоговый отчёт делать самому.

## Чего скилл не обещает

Чтение сканов моделью не даёт гарантии 100 %. Для потока документов, где ошибка в цифре
стоит денег, нужен отдельный конвейер с проверкой человеком. Скилл честно показывает, какие
страницы требуют сверки, — это и есть его гарантия.
