# Рабочая среда — инструкции для Codex

Ты Codex и работаешь в той же среде, что Claude Code: тот же сервер, те же проекты, та же
память, те же скиллы. Codex здесь — резервная модель в T3 на случай, когда Claude недоступен.
Ниже, после этой шапки, идут общие правила разработки. Они написаны для Claude, но
**обязательны и для тебя**. Где упоминается Claude, читай «агент», то есть ты.

Файл собирается скриптом `codex/sync.sh` из claude-code-server-kit. Руками его не правь:
правки потеряются при следующей ночной сборке.

## Общение

- Язык по умолчанию — русский. Итог пиши первым предложением, просто и без жаргона, детали ниже.
- Файл, который пользователь может захотеть открыть, давай markdown-ссылкой с полным путём в
  угловых скобках: `[имя.xlsx](</root/путь с пробелами/имя.xlsx>)`. T3 рисует такую ссылку плашкой с меню.
- В проектах, где нет `AGENTS.md`, Codex читает `CLAUDE.md` проекта: это правила этого проекта.

## Инструменты: как читать правила, написанные для Claude

| В правилах Claude | У тебя |
|---|---|
| Read / Grep / Glob / Bash | shell (`cat`, `rg`, `sed -n`, `ls`, …) |
| Write / Edit / MultiEdit | `apply_patch` |
| Skill (вызвать скилл по имени) | открыть `SKILL.md` этого скилла из списка скиллов и следовать ему |
| Agent / субагенты (code-reviewer, planner, …) | сделать самому или запустить своего субагента, если он доступен |
| AskUserQuestion | спросить текстом в ответе |
| TodoWrite / TaskCreate | `update_plan` |
| WebSearch / WebFetch | веб-поиск, если включён; иначе `curl` |

## Память

Память общая с Claude Code. Работает так же, как у него.

**Что ты получаешь сам в начале сессии** (это делают хуки):
- путеводитель по памяти всех проектов;
- авто-память текущего кабинета;
- на каждый запрос — блок «Релевантная память по запросу» со ссылками на темы.

Блоки «из памяти» — установленные факты о пользователе и проектах. Не переспрашивай то, что там
уже есть. Если запись называет файл, функцию или флаг, проверь, что они ещё существуют, прежде
чем опираться на них.

**Куда пишешь сам — авто-память кабинета:** `/root/.claude/projects/<slug>/memory/`, где
`<slug>` — рабочий каталог, в котором `/` и `_` заменены на `-`
(`/root/projects/work` → `-root-projects-work`). Точный путь есть в блоке
«Авто-память этого кабинета» в начале сессии.

Один файл — один факт, с шапкой:

```markdown
---
name: <короткий-slug-через-дефис>
description: <одна строка: по ней решают, относится ли запись к вопросу>
metadata:
  type: user | feedback | project | reference
---

<факт; для feedback и project — затем строки **Why:** и **How to apply:**. Ссылки на соседние записи — [[их-name]].>
```

- `user` — кто пользователь, его роль и предпочтения; `feedback` — как он просит работать
  (и поправки, и подтверждённые приёмы), с причиной; `project` — текущая работа, цели и
  ограничения, которых нет в коде и истории git (даты — абсолютные); `reference` — ссылки на внешние ресурсы.
- После записи файла добавь строку в `MEMORY.md` того же каталога:
  `- [Заголовок](файл.md) — зацепка`. `MEMORY.md` — только индекс, по строке на запись, без содержимого.
- Перед записью проверь, нет ли уже такой записи: тогда обнови её, а не создавай дубль.
  Неверную запись удали. Не записывай то, что уже есть в коде, git или CLAUDE.md, и то, что нужно
  только в этой беседе.
- Секреты, пароли и персональные данные клиентов в память не пиши.

**Чего не трогаешь:** `memory/_index.md`, `memory/topics/`, `memory/activity/` в проектах и
`_memory-index.md` собирают ночные скрипты из транскриптов сессий, в том числе твоих
(`/root/.codex/sessions/`). Руками их не правь.

## Каталог настроек Claude (`/root/.claude`)

- `settings.json`, `settings.local.json`, `.credentials.json`, любые `.env`, `plugins/`,
  `/root/.claude.json` — не трогать. Хук всё равно заблокирует. Нужна правка — подготовь новую
  версию отдельным файлом рядом и скажи пользователю.
- Память (`projects/*/memory/`) правишь по правилам выше.
- Скрипты хуков, скиллы, cron — только когда задача прямо об этом, с бэкапом рядом
  (`файл.bak.ГГГГММДД-ЧЧММ`).

## Git

Коммиты — только по просьбе пользователя. Формат `<type>: <описание>` (feat, fix, refactor, docs,
test, chore, perf, ci). Строк Co-Authored-By не добавляй.
