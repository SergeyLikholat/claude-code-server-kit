# Настройка автоматических бэкапов на Яндекс.Диск

> Это инструкция к модулю `backup`. Если просто хотите быстро установить — `sudo bash install.sh --module backup` сделает всё интерактивно. Этот документ — для понимания что происходит и для случаев когда нужно вручную.

---

## Зачем нужен бэкап

История повторяется. Партнёр одного из пользователей этого kit'а в мае 2026 потерял **весь** свой бизнес-кластер, когда полиция арестовала дата-центр в Нидерландах: серверы, данные, всё. Бизнесу был нанесён огромный ущерб.

Это не паранойя — это статистика:
- Сервера ломаются (диски умирают, провайдер банкротится)
- Аккаунты блокируют (нарушения, ошибки)
- Полиция приходит (политика, чужие соседи по серверу)
- Случайные действия (sudo rm -rf, не та команда)
- Атаки (ransomware, взлом)

**Бэкап стоит копейки. Не делать бэкап стоит всего.**

## Как работает наш бэкап

```
Каждую ночь в 03:00:
  ├─ pre-backup: дампы баз данных + копии важных файлов
  │   ├─ pg_dump для PostgreSQL
  │   ├─ sqlite backup для SQLite
  │   ├─ tar для docker volumes
  │   └─ копия crontab, systemd units, и т.п.
  │
  ├─ restic: шифрованный инкрементальный бэкап
  │   ├─ Файлы режутся на блоки по ~1-8 МБ
  │   ├─ Каждый блок хешируется
  │   ├─ Заливаются только новые/изменённые блоки
  │   └─ Всё шифруется AES-256 перед отправкой
  │
  ├─ rclone: загрузка на Яндекс.Диск
  │   └─ В папку /server-backups/restic-main/
  │
  ├─ retention: чистка старого
  │   └─ Оставить 7 ежедневных + 4 еженедельных + 6 месячных = 17 точек
  │
  └─ notify: уведомление в Telegram (если есть модуль tg-bot)
```

**Размер на Яндекс.Диске:** обычно 2-5 ГБ для среднего сервера. Растёт медленно благодаря дедупликации.

## Сравнение с другими решениями

| Решение | Плюсы | Минусы |
|---|---|---|
| **Наш kit (restic + Я.Диск)** | Шифрование, дедупликация, 17 точек, дёшево, российский провайдер | Только в РФ удобен (у Яндекса) |
| **Снапшот VPS у провайдера** | Один клик, восстановление быстрое | Привязан к провайдеру, нет шифрования у вас, стоит денег |
| **rsync на свой NAS** | Полный контроль | Нужен NAS дома, нужен публичный IP, нет шифрования |
| **Tarsnap** | Профессионально, бесплатно $0 за минимум | Очень дорого при росте, англоязычный |
| **AWS S3 + restic** | Надёжно | Платно с первого байта, западный провайдер |

Если вы в РФ — Яндекс.Диск выигрывает. Если за границей — можете переключить на S3 за 5 минут (см. [ADAPT.md](ADAPT.md)).

## Что вам потребуется

### 1. Яндекс.Диск

У вас он уже есть (с любой яндекс-почтой). Если хотите дополнительное место:
- Бесплатно: 5 ГБ
- Платно: 100 ГБ за ~100₽/мес, 1 ТБ за ~300₽/мес

Для среднего сервера хватает 5 ГБ. Если у вас много данных — апгрейдьте.

### 2. OAuth-приложение в Яндексе

Это нужно потому что rclone подключается к Я.Диску не через ваш логин/пароль (небезопасно), а через **OAuth-токен** — отдельный ключ который можно отозвать в любой момент без смены пароля.

**Создание (2 минуты, один раз):**

1. Откройте https://oauth.yandex.com/client/new
2. Заполните форму:
   - **Service name:** `server-backup-restic` (или любое)
   - **Platforms:** включите «Web services» → Redirect URI: `https://oauth.yandex.ru/verification_code`
   - **Data access:** в поиске «cloud_api:disk» → выберите все 4 (read, write, info, app_folder)
   - **Email address:** ваш
3. Нажмите «Create app»
4. На странице приложения скопируйте:
   - **ClientID** (длинный хэш)
   - **Client secret** (другой хэш)

⚠️ Когда Яндекс предложит «verify via Gosuslugi» — **закройте этот попап**. Верификация через Госуслуги не нужна для нашей задачи.

### 3. (Опционально) Telegram-бот

Если хотите чтобы статус бэкапа приходил в TG — установите сначала модуль `tg-bot`, потом `backup`. Бэкап автоматически подключится.

## Установка (интерактивная — самый простой путь)

```bash
sudo bash install.sh --module backup
```

Скрипт пошагово проведёт через:

### Шаг 1: Сохранение ClientID/Secret
```
Вставьте Yandex client_id: __________
Вставьте Yandex client_secret: __________
```

### Шаг 2: OAuth-авторизация

Скрипт покажет ссылку:
```
Откройте в браузере (на любом устройстве):
https://oauth.yandex.ru/authorize?response_type=code&client_id=<ваш>

Войдите в Яндекс, нажмите «Разрешить»
(увидите предупреждение Untrusted service — это нормально, ваше же приложение)

Скопируйте код (16 символов) с переадресованной страницы:
Код: __________
```

### Шаг 3: Генерация пароля шифрования

```
Генерирую restic-пароль (44 символа base64)...

⚠️ ВАЖНО — этот пароль покажется ОДИН раз:

   ВАШ_УНИКАЛЬНЫЙ_44_СИМВОЛЬНЫЙ_ПАРОЛЬ_БУДЕТ_ЗДЕСЬ

СОХРАНИТЕ ПРЯМО СЕЙЧАС:
   1. В Bitwarden / 1Password
   2. Распечатайте на бумаге, положите в сейф

Без этого пароля зашифрованный бэкап = непрочитаемая каша.
restic НЕ имеет recovery-механизма (это часть его безопасности).

Сохранили? (введите 'yes' для продолжения): yes
```

### Шаг 4: Папка на Я.Диске

```
В какую папку на Я.Диске заливать бэкап?
[по умолчанию: /server-backups/restic-main]: 
```

### Шаг 5: Тестовый бэкап

```
Запускаю тестовый бэкап... (1-5 минут)
✓ Snapshot создан: 4a2a41eb
✓ Размер на Я.Диске: 12 KB (тестовый файл)
✓ restic check: no errors
```

### Шаг 6: Расписание

```
Включить ежедневное расписание (cron 03:00)? [Y/n]: Y
✓ systemd timer enabled
Следующий запуск: завтра 03:04:56
```

### Шаг 7: Готово

```
==================== Установка backup завершена ====================

Что установлено:
  ✓ restic + rclone
  ✓ OAuth Яндекс настроен
  ✓ Шифрование AES-256, пароль в /root/.secrets/restic-password
  ✓ Ежедневный бэкап в 03:00 (через systemd timer)
  ✓ Retention: 7 daily + 4 weekly + 6 monthly = 17 точек

ВАЖНО:
  • Сохраните restic-пароль в Bitwarden и распечатайте
  • Сохраните client_id и client_secret в Bitwarden
  • Прочитайте RESTORE.md в директории backup/

Команды:
  • Ручной запуск:  sudo bash /opt/backup/scripts/backup.sh
  • Просмотр снимков:  restic snapshots
  • Восстановление:  см. backup/RESTORE.md
=========================================================================
```

## Установка через .env (без интерактива)

Если хотите без подсказок:

```bash
# В директории kit'а:
cat >> .env <<EOF
YANDEX_CLIENT_ID=ваш_id
YANDEX_CLIENT_SECRET=ваш_секрет
YANDEX_AUTH_CODE=код_из_oauth_страницы
BACKUP_TARGET_PATH=/server-backups/restic-main
BACKUP_RESTIC_PASSWORD=___СГЕНЕРИРУЙТЕ_САМИ___
EOF

sudo bash install.sh --module backup --non-interactive
```

⚠️ `BACKUP_RESTIC_PASSWORD` — если не укажете, скрипт сгенерирует и покажет в логе. Не забудьте сохранить.

## Что бэкапится

По умолчанию — список из [`backup/includes.template.txt`](../backup/includes.template.txt):

- `~/.claude/` — настройки Claude
- `~/.claude-mem/` — память (если модуль установлен)
- `~/.config/` — конфиги
- `~/.secrets/` — секреты
- `~/.ssh/` — SSH ключи
- `/opt/<ваши-модули>/` — установленные tools (БЕЗ ключей, они в `~/.secrets/`)
- `/etc/systemd/system/` — systemd-юниты
- `/var/backups/` — дампы БД (создаются pre-backup)
- (опционально) `/root/projects/` — ваши проекты

Чтобы добавить свои пути:
```bash
nano /opt/backup/includes.txt
# Добавьте строки с путями
```

### Что НЕ бэкапится (по умолчанию)

Из `backup/exclude.txt`:
- `node_modules`, `.venv`, `__pycache__` — пересоздаваемое
- `*.log`, `/var/log` — логи
- ML-модели (Parakeet, etc.) — качаются заново при необходимости
- Docker images — пересобираются из Dockerfile
- Кэши

См. [backup/RESTORE.md](../backup/RESTORE.md). Два сценария:

## Мониторинг

### Каждое утро смотрите статус

Если установлен `tg-bot` — в TG приходит уведомление автоматически:
```
✅ Backup OK
snapshot: 0d2b257e
размер: 2.74 GB
длительность: 10 мин 38 сек
```

Если нет TG — проверяйте вручную:
```bash
journalctl -u backup.service -n 30
restic snapshots --tag nightly
```

### Раз в месяц — глубокая проверка

```bash
restic check --read-data
```
Это перечитывает все блоки на Я.Диске и проверяет хеши. Полная гарантия целостности. Долго (час+), но раз в месяц стоит.

### Раз в квартал — тренировка восстановления

⚠️ **Без тренировки бэкап шрёдингеровский — жив пока не проверил.**

1. Арендуйте дешёвый VPS на час (Hetzner CPX21 = €0.05)
2. Пройдите по `backup/RESTORE.md` полностью
3. Если что-то пошло не так — обновите RESTORE.md под себя
4. Удалите тестовый VPS

Это страховка от того что в момент реальной аварии вы обнаружите что 6 месяцев бэкапы делались с ошибкой про которую никто не знал.

## Что хранить вне сервера

Эти артефакты должны быть **физически где-то ещё** на случай если сервер сгорит:

1. **Restic-пароль** — Bitwarden + бумажный резерв в сейфе. Без него бэкап не открыть никогда.
2. **Yandex client_id и client_secret** — Bitwarden. (refresh_token живёт на сервере и пропадёт с ним; client_id/secret позволят сгенерировать новый при DR.)
3. **Этот kit** — он на GitHub, всегда доступен.
4. **Ссылка на этот документ** — в Bitwarden, чтобы помнить куда лезть при DR.

## Если что-то идёт не так

См. [TROUBLESHOOTING.md](TROUBLESHOOTING.md) → раздел Backup.

Самое частое:
- **«restic check вернул ошибку lock»** — `restic unlock`, продолжайте
- **«rclone: unable to get RefreshToken»** — пройти OAuth заново (см. установку выше)
- **«Я.Диск качает медленно»** — нормально для Я.Диска (1-5 МБ/с), запускайте restore в `tmux`
