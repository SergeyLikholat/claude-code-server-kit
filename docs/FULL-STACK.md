# Полная среда Claude на своём сервере

Одна команда ставит на чистый VPS всё, что нужно для работы с Claude из браузера и с телефона:
сам Claude Code, правила и навыки, память между сессиями и T3, через который вы с ним работаете.
Ключи заполняются один раз в одном файле, дальше установщик ничего не спрашивает.

## Что ставится: пять слоёв

| Слой | Что это | Чем ставится | Что нужно от вас |
|---|---|---|---|
| 1. Сервер | Ubuntu, системные пакеты, Node.js, Python, фаервол | core (`setup/core/01-prereqs.sh`) | VPS с root-доступом |
| 2. Claude Code и вход | Программа `claude` и вход в подписку | core (`02-claude-cli.sh`) + токен из `secrets.env` | Подписка Claude Pro или Max |
| 3. Обвязка `~/.claude` | Настройки, права, агенты, навыки, правила | core (`03-ecc-base.sh`, `04-minimal-config.sh`) | Ничего |
| 4. Память | Путеводитель по памяти при старте сессии, релевантные заметки на каждый запрос, ночная сборка тем | модуль `memory` (ставит [llm-memory-kit](https://github.com/SergeyLikholat/llm-memory-kit)) | Ничего |
| 5. T3 | Окно к Claude в браузере и Android-приложении, свой домен с https | модуль `t3` | Домен и архив сборки от администратора |

T3 сам агента не содержит. Он запускает установленный на сервере `claude`, а тот берёт хуки,
правила, навыки и память из `~/.claude`. Поэтому слои 2–4 работают и без T3, например в терминале.

Модули по желанию ставятся, если для них есть ключ: `backup` (бэкап на Яндекс.Диск),
`tg-bot` (Telegram-бот), `helpers` (Excel без сбоев, генерация картинок и озвучка через Gemini),
`parakeet` (распознавание голоса). Подробно о каждом — [MODULES.md](../MODULES.md).

## Порядок: от VPS до ссылки

1. **Получить VPS.** Ubuntu 22.04 или 24.04, от 2 ГБ памяти (с Parakeet — от 4 ГБ), root-доступ по SSH.
2. **Направить домен.** У регистратора домена создать A-запись: например, `t3.example.ru` указывает на IP сервера.
   Пока запись расходится (5–30 минут), можно делать следующие шаги.
3. **Заполнить `secrets.env`.** Обычно его готовит администратор: копирует
   `secrets.example.env`, вписывает домен, архив T3 и по желанию Telegram, Gemini, Яндекс.Диск.
   Вы добавляете только свой токен Claude (как его получить — ниже).
4. **Положить файл на сервер и запустить установку:**

   ```bash
   git clone https://github.com/SergeyLikholat/cc-multiuser-kit.git kit && cd kit
   # secrets.env положить сюда же (scp или вставить в nano)
   sudo bash install.sh --full --secrets secrets.env --delete-secrets
   ```

   Сначала установщик проверяет каждый ключ. Если что-то не так, он останавливается до
   установки и пишет, какой ключ неверный и где взять правильный. Потом ставит всё по порядку,
   это занимает 10–20 минут.
5. **Открыть приглашение.** В конце установщик печатает ссылку-приглашение и QR-код. Она
   одноразовая и действует час:
   - на компьютере её открывают в браузере;
   - на Android скачивают приложение по адресу из итога (`https://<домен>/t3-apk/T3-Code.apk`),
     устанавливают, добавляют сервер и вставляют приглашение;
   - на iPhone открывают приглашение в Safari и добавляют на экран «Домой».

Новая ссылка для второго устройства:

```bash
t3 auth pairing create --base-url https://<домен> --ttl 1h
```

## Где взять каждый ключ

Шаблон со всеми ключами — [`secrets.example.env`](../secrets.example.env).

| Ключ | Обязателен | Где взять |
|---|---|---|
| `CLAUDE_CODE_OAUTH_TOKEN` | да | На любом компьютере с Claude Code выполнить `claude setup-token`, войти на claude.ai по ссылке и скопировать `sk-ant-oat01-…`. Действует год |
| `T3_DOMAIN` | для T3 | Ваш домен или поддомен, A-запись которого смотрит на сервер |
| `ACME_EMAIL` | для T3 | Любая ваша почта. На неё придёт письмо, если сертификат не продлится |
| `T3_TARBALL` | для T3 | Путь или ссылка на архив сборки от администратора (как его сделать — ниже) |
| `T3_APK` | нет | Файл Android-приложения от администратора |
| `TELEGRAM_BOT_TOKEN` | нет | Команда `/newbot` в чате [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | нет | Написать боту, открыть `https://api.telegram.org/bot<токен>/getUpdates`, взять `chat.id` |
| `GEMINI_API_KEY` | нет | [aistudio.google.com/apikey](https://aistudio.google.com/apikey). С российских IP Gemini не работает |
| `RCLONE_YANDEX_TOKEN` | нет | На компьютере с браузером: установить [rclone](https://rclone.org/install/), выполнить `rclone authorize "yandex"`, войти в Яндекс, скопировать строку `{"access_token":…}` целиком, в одинарных кавычках |
| `RESTIC_PASSWORD` | нет | Придумать от 12 символов или оставить пустым: установщик сгенерирует сам. Сохраните в менеджер паролей, без него бэкап не восстановить |
| `HF_TOKEN` | нет | [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens), тип read. Нужен, только если скачивание модели Parakeet упирается в лимиты |

Как проверяются ключи:

- Claude: запрос списка моделей к API Anthropic с вашим токеном. Он бесплатный и лимиты
  подписки не тратит. `claude auth status` для проверки не годится: он считает вход выполненным при
  любой строке в токене. Если API ответил неоднозначно, установщик делает один короткий запрос
  через `claude -p` моделью haiku во временной папке, не затрагивая ваших настроек.
- Telegram: `getMe`, а при заданном чате ещё `getChat`, бот должен видеть этот чат. Сообщений бот не отправляет.
- Gemini: запрос списка моделей.
- Яндекс.Диск: `rclone lsd` на временной настройке. Если rclone ещё не установлен, запрос идёт к API Диска.
- Домен: есть ли A-запись и совпадает ли она с адресом сервера.

## Куда попадает токен Claude

После установки ключи лежат в `~/.config/kit/secrets.env` (права 600, читает только владелец).
Токен Claude, кроме того, записан отдельно в `~/.config/kit/claude.env` — одной строкой, чтобы
службы и фоновые задачи получали только его, без токенов Telegram и бэкапа. Файл читают:

| Кто | Как |
|---|---|
| T3 и все треды в нём | служба `t3code.service`: `EnvironmentFile=-%h/.config/kit/claude.env` |
| Терминал (SSH, терминал в T3) | блок в `~/.bashrc` подключает `claude.env` |
| Ночные сборщики памяти | `config.sh` llm-memory-kit подключает `claude.env` |
| Любые свои задачи cron | обёртка `kit-env`: `0 3 * * * kit-env claude -p "…"` |

Продлить токен (раз в год) или заменить любой другой ключ:

```bash
claude setup-token                                   # на любом компьютере — новый токен
nano ~/.config/kit/secrets.env                       # заменить значение CLAUDE_CODE_OAUTH_TOKEN
sudo bash install.sh --apply-secrets                 # проверка, сохранение, перезапуск T3
```

## Для администратора: архив T3 и приложение

T3 ставится на чужие серверы готовой сборкой с нашими патчами — компилировать на VPS ничего не нужно.

```bash
cd t3-patches
./update.sh v0.0.43          # собрать сборку с патчами на своём сервере (подробно — README.md там же)
./package.sh 0.0.43-s18      # упаковать: dist/t3-0.0.43-s18-linux-x64.tar.gz + .sha256
```

Архив и файл `.sha256` выложить по https (релиз на GitHub, свой сервер) или передать на сервер
через `scp`, затем указать путь или ссылку в `T3_TARBALL`. Сумма рядом с архивом проверяется сама.
APK лежит в `t3-patches/apk/`; указать его в `T3_APK`, и он будет раздаваться с домена человека.

Обновить T3 на уже работающем сервере:

```bash
t3-update https://…/t3-0.0.43-s18-linux-x64.tar.gz   # поставить рядом, переключить, проверить
t3-update rollback                                   # вернуть прежнюю версию
t3-update status                                     # что стоит и работает ли
```

`t3-update` ставит новую версию рядом со старой, переключает ссылку `~/.local/bin/t3`, перезапускает
службу и ждёт, пока она ответит. Если за две минуты служба не поднялась, он сам возвращает прежнюю
версию. При запуске из терминала внутри T3 перезапуск уходит в отдельную задачу systemd, поэтому
открытые сессии оборвутся, но треды и история сохранятся.

## Что где лежит на сервере

| Путь | Что |
|---|---|
| `~/.config/kit/secrets.env` | все ключи (600) |
| `~/.config/kit/claude.env` | только токен Claude (600) |
| `~/.config/kit/t3.env` | порт и домен T3 для `t3-update` |
| `~/.t3/runtime/versions/<версия>/` | сборки T3, текущая — по ссылке `~/.local/bin/t3` |
| `~/.config/systemd/user/t3code.service` | служба T3 |
| `/etc/caddy/sites-kit/t3.caddy` | сайт T3 в Caddy |
| `/srv/kit-t3-apk/` | APK для скачивания с домена |
| `~/llm-memory-kit/` | память: скрипты, хуки, `config.sh` |
| `~/projects/<проект>/memory/` | память проектов |
| `/var/lib/claude-code-server-kit/` | какие модули стоят, итог установки T3 |

Пользователь среды по умолчанию — root, как на сервере-образце. Другой: `KIT_USER=ivan` перед
командой установки.

## Если что-то пошло не так

- **Установщик остановился на проверке ключей.** На сервере ничего не менялось. Исправьте
  значение, на которое он указал, и запустите ту же команду снова.
- **https не открывается.** Проверьте A-запись (`getent hosts <домен>` должен вернуть IP сервера)
  и что провайдер не закрывает порты 80 и 443. Журнал Caddy: `journalctl -u caddy -n 50`.
- **Caddy уже работает в Docker или порты заняты nginx.** Модуль t3 чужую настройку не трогает,
  а печатает готовый блок для вашего прокси. После настройки прокси достаточно получить новую
  ссылку-приглашение.
- **Треды в T3 падают сразу.** Проверьте токен: `sudo bash install.sh --check`, затем
  `journalctl --user -u t3code -n 50`.
- **Ссылка-приглашение истекла.** Получите новую командой из раздела «Порядок».
- **Модуль упал, остальные встали.** Итог установки показывает, какой именно. Повторить его одного:
  `sudo bash install.sh --module <имя>`. Сохранённые ключи подхватятся сами.
