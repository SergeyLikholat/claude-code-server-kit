# Настройка SSH-ключей — простыми словами

> Эта инструкция для тех кто **никогда не настраивал серверы**. Если вы технически подкованы — можете сразу прыгнуть в [TL;DR в конце](#tldr-для-технарей).

---

## Зачем это вообще нужно

Когда вы купили VPS (виртуальный сервер), провайдер выдал вам **IP-адрес** и **пароль для root**. Вы можете подключиться по паролю — и это работает, но:

❌ **Это небезопасно.** Боты в интернете постоянно сканируют серверы и подбирают пароли. Если пароль слабый — взломают за часы.

❌ **Это неудобно.** Каждый раз вводить пароль вручную.

❌ **Это нельзя автоматизировать.** Скрипты не могут «вводить пароль за вас» — им нужны ключи.

**Решение — SSH-ключи.** Это пара файлов:
- **Приватный ключ** — лежит у вас на компьютере (никому не показываете)
- **Публичный ключ** — кладёте на сервер (можно показывать)

Когда вы подключаетесь, ваш компьютер с приватным ключом «доказывает» серверу что это именно вы — без ввода пароля и без передачи самого пароля. Это **математически невзламываемо**, в отличие от пароля.

Аналогия: вместо того чтобы каждый раз называть кодовое слово (которое могут подслушать), вы показываете уникальную печать, которую невозможно подделать.

## Windows

### Шаг 1: Откройте PowerShell

1. Нажмите **Win + R** одновременно
2. Напечатайте: `powershell`
3. Нажмите **Enter**

Откроется тёмное окно с белым текстом — это и есть PowerShell, ваш «терминал».

### Шаг 2: Создайте SSH-ключ

В открывшемся окне напечатайте (или скопируйте и вставьте правой кнопкой мыши):

```powershell
ssh-keygen -t ed25519 -C "ваше_имя@вашпк"
```

Например:
```powershell
ssh-keygen -t ed25519 -C "ivan@home-pc"
```

Что произойдёт:
- Компьютер спросит **«куда сохранить файл»** — нажмите Enter (по умолчанию `C:\Users\ВашеИмя\.ssh\id_ed25519` — это правильно)
- Спросит **«придумайте пароль для ключа»** — можете нажать Enter дважды (без пароля), или придумать пароль (тогда придётся вводить его при каждом подключении — менее удобно но безопаснее)

Результат:
```
Your identification has been saved in C:\Users\Ivan\.ssh\id_ed25519
Your public key has been saved in C:\Users\Ivan\.ssh\id_ed25519.pub
```

🎉 Готово, ключи созданы. Приватный — `id_ed25519` (НЕ ПОКАЗЫВАЙТЕ НИКОМУ), публичный — `id_ed25519.pub` (его и положим на сервер).

### Шаг 3: Покажите содержимое публичного ключа

```powershell
type $HOME\.ssh\id_ed25519.pub
```

Появится длинная строка, начинается с `ssh-ed25519 AAAA...` и заканчивается вашим именем. **Выделите всё это мышкой и скопируйте** (правая кнопка → Копировать). Это ваш публичный ключ.

### Шаг 4: Подключитесь к серверу по паролю и положите туда ключ

В том же PowerShell:

```powershell
ssh root@IP_АДРЕС_ВАШЕГО_СЕРВЕРА
```

Например:
```powershell
ssh root@192.168.1.100
```

- Спросит «Are you sure you want to continue connecting?» → напечатайте `yes`, Enter
- Спросит пароль root → введите (символы не отображаются — это нормально)

Вы внутри сервера. Теперь выполните на сервере:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "ВСТАВЬТЕ_СЮДА_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

Замените `ВСТАВЬТЕ_СЮДА_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ` на ту длинную строку которую вы скопировали в Шаге 3 (правая кнопка мыши → Вставить).

⚠️ **Важно про копипасту ключей.** Если вы копируете содержимое **приватного** ключа (например, чтобы перенести его на другую машину) — часто теряется финальный перенос строки. OpenSSH считает такой ключ битым и молча уходит на пароль, без внятной ошибки. Если ключ перестал работать после копирования — проверьте:
```bash
ssh-keygen -y -f ~/.ssh/id_ed25519   # должно вывести публичную часть; если ошибка — ключ битый
tail -c 1 ~/.ssh/id_ed25519 | xxd    # должно быть `0a` (newline) в конце
```
Если нет финального newline — допишите: `printf '\n' >> ~/.ssh/id_ed25519` или пересоздайте ключ.

Выйдите из сервера:
```bash
exit
```

### Шаг 5: Проверьте что работает без пароля

```powershell
ssh root@IP_АДРЕС_ВАШЕГО_СЕРВЕРА
```

Если **не спросило пароль** — ✅ ключи работают.

Если всё ещё спрашивает пароль — посмотрите [Что делать если не работает](#что-делать-если-не-работает).

### Опционально: настройте VS Code на использование ключа

Если используете VS Code Remote-SSH, он автоматически найдёт ваш ключ в `C:\Users\ВашеИмя\.ssh\` и подхватит. Просто переподключитесь к серверу — пароль уже не спросит.

➡️ Дальше: запустите `preflight-ssh.sh` на сервере, чтобы **отключить вход по паролю совсем** (опционально, но рекомендуется). Или сразу переходите к [установке Claude Code](../README.md#установка-за-5-минут).

## Mac

### Шаг 1: Откройте Terminal

1. Нажмите **Cmd + Пробел** одновременно
2. Напечатайте: `Terminal`
3. Нажмите **Enter**

Откроется окно терминала.

### Шаг 2: Создайте SSH-ключ

В терминале напечатайте (или скопируйте):

```bash
ssh-keygen -t ed25519 -C "ваше_имя@macbook"
```

Например:
```bash
ssh-keygen -t ed25519 -C "ivan@macbook"
```

- Спросит куда сохранить → нажмите Enter (по умолчанию `~/.ssh/id_ed25519`)
- Спросит пароль → Enter дважды (без пароля), или придумайте свой

🎉 Ключи созданы.

### Шаг 3: Скопируйте публичный ключ

На Mac есть удобная команда что сразу копирует ключ в буфер обмена:

```bash
pbcopy < ~/.ssh/id_ed25519.pub
```

Ключ уже в буфере, можете вставить (Cmd+V) где угодно.

Или показать на экране:
```bash
cat ~/.ssh/id_ed25519.pub
```

### Шаг 4: Положите ключ на сервер

В терминале подключитесь к серверу:

```bash
ssh root@IP_АДРЕС_СЕРВЕРА
```

- Подтвердите подключение (`yes`), Enter
- Введите пароль root

На сервере:
```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "ВСТАВЬТЕ_СЮДА_ВАШ_КЛЮЧ" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
exit
```

Замените `ВСТАВЬТЕ_СЮДА_ВАШ_КЛЮЧ` на содержимое буфера обмена (Cmd+V).

### Шаг 5: Проверьте

```bash
ssh root@IP_СЕРВЕРА
```

Если без пароля — ✅ работает.

### Альтернатива: ssh-copy-id (одна команда)

Если есть утилита `ssh-copy-id` (обычно есть на свежих Mac), можете сделать всё в одну команду вместо Шагов 3-4:

```bash
ssh-copy-id root@IP_СЕРВЕРА
```

Введёте пароль один раз, утилита сама всё положит куда надо.

➡️ Дальше: [установка Claude Code](../README.md#установка-за-5-минут).

## Linux

Скорее всего вы и так знаете что делать, но на всякий случай:

### Шаг 1: Откройте терминал

`Ctrl + Alt + T` (Ubuntu/Mint/большинство DE).

### Шаг 2: Создайте ключ (если ещё нет)

```bash
ssh-keygen -t ed25519 -C "$(whoami)@$(hostname)"
```

Enter на все вопросы (или придумайте passphrase).

### Шаг 3: Скопируйте на сервер одной командой

```bash
ssh-copy-id root@IP_СЕРВЕРА
```

Если `ssh-copy-id` нет — устанавливается из репозитория:
```bash
sudo apt install openssh-client    # Debian/Ubuntu
sudo dnf install openssh-clients   # Fedora
```

### Шаг 4: Проверка

```bash
ssh root@IP_СЕРВЕРА
```

Без пароля → ✅

➡️ Дальше: [установка Claude Code](../README.md#установка-за-5-минут).

## Дополнительная защита (рекомендуется)

После того как ключи работают, можно **полностью отключить вход по паролю**. Это сильно повышает безопасность — даже если кто-то узнает ваш пароль, без ключа войти не сможет.

Это делает скрипт `preflight-ssh.sh` из этого репозитория. На сервере выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyLikholat/claude-code-server-kit/main/preflight-ssh.sh | bash
```

Скрипт:
- Проверит что у вас есть рабочий SSH-ключ
- Спросит подтверждение что вы готовы отключить пароль (если ключ не работает — это сломает доступ!)
- Опционально предложит поменять стандартный порт SSH (22 → что-то менее банальное)
- Опционально поставит fail2ban (автоматически блокирует ботов которые перебирают доступ)

⚠️ **ВАЖНО:** не отключайте вход по паролю если не уверены что ключ работает. Если что-то пойдёт не так — потеряете доступ к серверу. **Сначала проверьте что без пароля заходит,** только потом запускайте preflight-ssh.sh.

## Что делать если не работает

### «Permission denied (publickey)»

Ключ не подхватился. Проверьте:

1. На сервере есть файл `~/.ssh/authorized_keys` с правильным содержимым:
   ```bash
   ssh root@IP_СЕРВЕРА   # войти по паролю
   cat ~/.ssh/authorized_keys
   # должна быть ваша длинная строка ssh-ed25519 AAAA...
   ```

2. Права на файлы правильные:
   ```bash
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys
   ```

3. На вашем компьютере приватный ключ есть:
   - Windows: `C:\Users\ВашеИмя\.ssh\id_ed25519`
   - Mac/Linux: `~/.ssh/id_ed25519`

### «Connection refused»

Сервер не отвечает или не запущен SSH. Проверьте:
- VPS включён в панели провайдера
- IP-адрес правильный

### «Host key verification failed»

Возможно вы пересоздавали сервер с тем же IP. Удалите старую запись:
```bash
ssh-keygen -R IP_СЕРВЕРА
```
И подключайтесь заново.

### Я отключил вход по паролю и теперь не могу войти

Если у вас нет работающего ключа — единственный способ восстановить доступ это **консоль через панель провайдера** (KVM или Recovery-режим). Каждый провайдер делает это по-своему — ищите в их документации «доступ через консоль» или «recovery mode».

В консоли можете:
```bash
sudo nano /etc/ssh/sshd_config
# Найдите строку PasswordAuthentication no, измените на yes
sudo systemctl restart sshd
```

И снова сможете подключаться по паролю чтобы заново настроить ключ.
