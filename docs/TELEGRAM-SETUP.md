# Настройка Telegram-бота

> Инструкция к модулю `tg-bot`. Цель — установить бота за 15-30 минут с нуля.

---

## Что вы получите

Личный Telegram-бот, через которого вы будете общаться со своим Claude Code на сервере:
- Пишете сообщение в TG → бот передаёт Claude → Claude отвечает в TG
- Можете отправлять текст, голосовые, фото, файлы
- Поддерживается «форум-группа» с топиками — разные проекты в разных топиках
- Уведомления от других модулей (бэкап, мониторинг) приходят сюда же

---

## Шаг 1: Создайте бота через BotFather

1. Откройте Telegram, найдите **[@BotFather](https://t.me/BotFather)** (официальный бот Telegram)
2. Напишите ему: `/newbot`
3. Придумайте **отображаемое имя** (любое, например «Мой Claude»)
4. Придумайте **username** — должен заканчиваться на `_bot`, быть уникальным:
   - Например `IvanovClaudeAssistant_bot`
   - Если занято — попробуйте другой
5. BotFather пришлёт **токен** вида:
   ```
   123456789:ABCdef1234ghIklZyxWvuT5g4FjHsm6E7N
   ```
   Это **секрет** — никому не показывайте.

### Полезные настройки бота (опционально)

В чате с BotFather:
- `/setdescription` → описание которое видят пользователи
- `/setuserpic` → аватарка
- `/setcommands` → подсказки команд (например `/help`)

### Важно — отключите Privacy Mode для работы в группах

По умолчанию бот в группах видит **только** сообщения адресованные ему (`@bot_name ...` или ответ на его сообщение). Для удобства можно разрешить ему видеть все:

```
/mybots → выберите бота → Bot Settings → Group Privacy → Turn off
```

⚠️ Это значит бот будет «слышать» все сообщения в группах куда его добавили. Делайте только если бот в **личных** группах (не публичных).

---

## Шаг 2: Создайте группу для общения

Можно использовать существующую группу или создать новую.

### Вариант A: Обычная группа (просто)

1. В TG: создать группу → добавить **только себя и бота**
2. Назовите как-нибудь: «Claude», «AI Assistant», что хотите

### Вариант B: Форум-группа (рекомендуется для нескольких проектов)

Форум-режим даёт «топики» внутри группы — это как папки. У вас может быть топик «Работа», «Личное», «Бэкап-уведомления» и т.д.

1. Создайте обычную группу
2. Сделайте её супергруппой: добавьте >5 человек (можно своих ботов) или включите историю для новых участников
3. В настройках группы → **Topics → On**
4. Создайте топики (правый верх → New topic)

## Шаг 3: Узнайте chat_id вашей группы

Это число вида `-1001234567890` (для супергрупп начинается с `-100`). Нужно чтобы бот знал куда писать.

### Самый простой способ

1. Добавьте в группу бота **[@username_to_id_bot](https://t.me/username_to_id_bot)** (или любого аналогичного)
2. Он покажет ID группы
3. Удалите бота из группы

### Через ваш собственный бот (после установки)

Если уже установили модуль, в логах сервера:
```bash
journalctl -u tg-router -f
```
Напишите любое сообщение в группу → в логах увидите `chat.id: -100...`.

## Шаг 4: Запустите установку модуля

На сервере, в директории kit'а:

```bash
sudo bash install.sh --module tg-bot
```

Скрипт спросит:

```
Telegram Bot Token (от @BotFather):
> 123456789:ABCdef...

Telegram Chat ID (группа куда бот пишет, например -1001234567890):
> -1001234567890

Использовать форум-режим с топиками? [y/N]:
> y

Если форум — введите thread_id топика "general" (по умолчанию 1):
> 1
```

Скрипт:
- Скопирует код бота в `/opt/claude-telegram-router/`
- Сохранит токен в `/root/.claude/channels/telegram/.env` (chmod 600)
- Создаст systemd-юнит `tg-router.service` с `Restart=always`
- **Включит автозапуск (`systemctl enable`)** — после перезагрузки сервера бот сам запустится
- Запустит и проверит что бот отвечает

### Автозапуск после перезагрузки

`tg-router.service` устанавливается **enabled** — это значит:
- После `reboot` сервера бот запустится автоматически
- Если бот упал (ошибка / OOM) — systemd рестартует через 5 секунд (`Restart=always`)
- Проверить что enabled: `systemctl is-enabled tg-router` → должно быть `enabled`
- Логи перезапусков: `journalctl -u tg-router -n 100`

### Второй бот (опционально)

Если нужен **второй бот** на том же сервере (например, для семьи / команды / разделения личного и рабочего):

```bash
sudo bash install.sh --module tg-bot -- --second-bot
```

Установит отдельный systemd-юнит `tg-router2.service` с независимым:
- Кодом в `/opt/claude-telegram-router2/`
- Конфигом в `/root/.claude/channels/telegram2/.env`
- Lock-директорией `/run/claude-telegram2/`
- Также `enabled` (автозапуск)

Боты работают параллельно, не конфликтуют.

## Шаг 5: Проверка работы

В группе напишите:
```
Привет!
```

Бот должен через 5-10 секунд переслать ваше сообщение в Claude, а ответ Claude — обратно в группу.

Если что-то пошло не так — см. [Troubleshooting](#troubleshooting) ниже.

## Как пользоваться

### Простое сообщение

Просто пишите боту/в группу что хотите чтобы Claude сделал:
```
Прочитай файл /root/notes/idea.md и подскажи как развить идею
```

Бот передаст в Claude, ответ придёт в TG.

### Голосовое сообщение

Если установлен модуль `parakeet`:
1. Запишите голосовое в TG (зажмите микрофон)
2. Бот скачает, расшифрует, передаст текст в Claude
3. Claude ответит

Без `parakeet` расшифровки не будет — Claude получит сам файл.

Транскрипция работает в двух режимах, роутер выбирает сам:

- если в `.env` задан `PARAKEET_URL` (модуль `parakeet` прописывает его
  автоматически) — запрос уходит в `parakeet-server` по HTTP;
- иначе вызывается локальный скрипт `/opt/parakeet/transcribe.py` напрямую;
  путь переопределяется переменной `PARAKEET_SCRIPT`.

Если HTTP-сервис не ответил, роутер пробует локальный скрипт как запасной путь.

### Фото

Прикрепите фото к сообщению:
```
Что на этой картинке? Опиши подробно.
```
(Claude умеет работать с изображениями, бот пересылает их в чат)

### Файлы

Прикрепите PDF/TXT/DOCX/что угодно:
```
Прочитай этот файл и сделай summary
```

### Команды для бота

В чате с ботом (или в группе):

| Команда | Что делает |
|---|---|
| `/help` | справка по доступным командам |
| `/status` | сессия топика, выбранная модель, занятость контекста |
| `/model` | выбрать модель для текущей сессии (см. ниже) |
| `/list`, `/connect`, `/disconnect` | работа с реестром сессий (bridge-топик) |
| `/digest`, `/reset`, `/rollback` | обслуживание контекста топика |

### Выбор модели — `/model`

Воркер запускается как `claude --print`, и **без явного флага `--model` CLI
резолвит собственный дефолт**, который не совпадает с моделью, выбранной для
той же сессии в VS Code, и меняется со временем. Из-за этого сессия могла
молча переключать модель между сообщениями.

`/model` показывает пикер и закрепляет выбор **за сессией** (не за топиком —
bridge-топик можно перенаправить на другую сессию, и настройка останется при
своей работе). Состояние хранится в `model.json` рядом с `routing.json`.

Режимы:

| Режим | Поведение |
|---|---|
| **Следовать за VS Code** (по умолчанию) | Читает модель последнего VS Code-турна из JSONL сессии и передаёт её воркеру. Если турнов VS Code нет — запасная модель. |
| **Закрепить модель** | Всегда передавать выбранный `--model`. |
| **AUTO** | Не передавать флаг вообще, отдать резолв CLI (будет дрейфовать). |

`/status` показывает, как настройка разрешается прямо сейчас: «синхронно с
VS Code», «закреплено вручную» или «решает CLI (дрейфует)». Новая модель
применяется со следующего сообщения.

### Сообщения во время работы (досыл)

Если написать в топик, пока идёт ответ, сообщение **не потеряется и не
смешается** с текущим ходом: оно встаёт в очередь (до 20 штук), приходит
подтверждение «➕ принято» и кнопка **⚡ Перебить сейчас**. Накопленное
запускается отдельным ходом сразу после завершения текущего; кнопка обрывает
текущий проход, если он уже неактуален.

Очередь живёт в памяти процесса — рестарт `tg-router` между ходами её теряет.

## Использование топиков (если форум-режим)

Если включили форум, можете создать топики под проекты:
- **Топик «Личное»** — личные задачи, идеи
- **Топик «Работа: Проект А»** — кодинг по проекту А, Claude подгружает контекст проекта
- **Топик «Бэкап»** — сюда приходят уведомления о бэкапах
- **Топик «Мониторинг»** — алерты от других сервисов

Чтобы Claude автоматически подгружал контекст проекта в зависимости от топика — отредактируйте `/root/.claude/channels/telegram/routing.json` (создаётся при установке модуля с дефолтным `general`-топиком):

```json
{
  "general": {
    "name": "General",
    "project_dir": "/root",
    "session_id": "00000000-0000-0000-0000-000000000001"
  },
  "topics": {
    "10": {
      "name": "Project A",
      "project_dir": "/root/projects/project-a",
      "session_id": "11111111-1111-1111-1111-111111111111"
    },
    "20": {
      "name": "Project B",
      "project_dir": "/root/projects/project-b",
      "session_id": "22222222-2222-2222-2222-222222222222"
    }
  }
}
```

- Ключи в `topics` — это `message_thread_id` форум-топиков (видно в логах: `journalctl -u tg-router -f`).
- `project_dir` — рабочая директория, под которой запустится Claude (CLAUDE.md этого каталога автоматически попадёт в контекст).
- `session_id` — UUID, ОДИН на топик; роутер сам решает `--resume` или `--session-id` по наличию файла `~/.claude/projects/<slug>/<session_id>.jsonl`.

После правки рестарт не нужен — `routing.json` перечитывается на каждое входящее сообщение.

## VS Code Live — управление любой VS Code сессией из TG

Это специальный режим топика, через который можно «подключаться» к любой открытой Claude Code сессии в VS Code прямо из Telegram. Подходит когда:
- Сидишь за ноутом, открыта сессия в VS Code → встал, пошёл — продолжаешь общаться с ней с телефона.
- Сделал что-то в VS Code, надо догнать на ходу — `/list` → `/connect 1` → пишешь как обычно.
- На сервере одновременно живут несколько проектных сессий, надо переключаться между ними без редактирования `routing.json`.

### Как работает

Bridge-режим сканирует `~/.claude/projects/<slug>/*.jsonl` — все живые сессии Claude Code на сервере, отфильтровывает уже привязанные к TG-топикам (чтобы не было путаницы) и предлагает выбрать любую через `/list`. После `/connect <N>` все следующие сообщения в этом топике уходят в выбранную сессию через `--resume`.

### Топик в routing.json

В `/root/.claude/channels/telegram/routing.json` добавляется специальный топик с `mode: "vscode_bridge"`:

```json
{
  "topics": {
    "2723": {
      "name": "VS Code Live",
      "mode": "vscode_bridge",
      "project_dir": "/root",
      "session_id": "_BRIDGE_PLACEHOLDER_"
    }
  }
}
```

- `2723` — `message_thread_id` форум-топика «VS Code Live» в твоей TG-группе.
- `_BRIDGE_PLACEHOLDER_` — фиктивный session_id; реальный приходит из стейт-файла `vscode_bridge.json` после `/connect`.

### Команды (работают только в bridge-топике)

| Команда | Что делает |
|---|---|
| `/list` | Список последних VS Code сессий (страницы по 10, кнопки-номера для быстрого `/connect`) |
| `/list 2` | Перейти на страницу 2 |
| `/list all` | Включая claude-mem observer-сессии (обычно скрыты) |
| `/connect 1` | Привязать топик к сессии №1 из списка |
| `/connect a3f4` | Привязать по префиксу session_id (минимум 4 символа) |
| `/disconnect` | Отвязать топик от сессии |
| `/status` | Сколько сообщений / размер JSONL подключённой сессии |

Inline-клавиатура: под `/list` — кнопки `1 2 3 4 5`, `‹ 2/4 ›` и сверху `➕ Новая сессия`; под `🟢 Подключено` — `📥 Свежий ответ`, `📋 Сменить`, `⏹ Отвязать`.

### Создание новой сессии прямо из Telegram

Кнопка **`➕ Новая сессия`** (есть под `/list` и под сообщением «Отключено») создаёт чистую пустую сессию **не выходя из Telegram** — аналог «+ New session» в VS Code Sidebar. Жмёшь кнопку → генерируется свежий `session_id`, топик к нему привязывается, первое же твоё сообщение начинает новый диалог с нуля. Такие сессии **автоматически появляются в VS Code Sidebar** (демон патчит JSONL: `entrypoint sdk-cli → claude-vscode` + синтетический заголовок), помеченные `📱 Новая (TG)`.

### Bridged-режим: как Claude отвечает в VS Code Live

В обычных топиках Claude отправляет ответ через MCP-инструмент `reply`. В bridge-топике это **отключено** — вместо этого:

1. Claude пишет ответ как обычное assistant-сообщение (Markdown) — MCP Telegram-инструменты ему не выдаются (`ALLOWED_TOOLS_BRIDGED`).
2. Демон после завершения хода **сам забирает финальный ответ из JSONL** и шлёт в Telegram, конвертируя Markdown → Telegram HTML (`**жирный**`, `` `код` ``, ` ```блоки``` `, ссылки, заголовки).
3. Под ответом появляется **floating control panel** (`🎛 управление сессией`) с быстрыми кнопками — всегда внизу чата, без скролла наверх.

Кнопка **`📥 Свежий ответ`** (pull) — если сессия ещё работает (например долгая задача), нажми её чтобы дотянуть последний готовый ответ из сессии вручную. Демон отслеживает `last_pulled_uuid`, поэтому дубли не присылаются, а если новый ответ ещё не готов — покажет «🔄 Сессия работает».

### Установка на чистый сервер

Включить сразу при установке tg-bot:

```bash
VSCODE_LIVE_THREAD_ID=2723 sudo bash install.sh --module tg-bot -- --with-vscode-live
```

(подставь свой `message_thread_id` форум-топика — узнать можно через `journalctl -u tg-router -f` после первого сообщения в нужный топик).

### Доустановка на УЖЕ работающий сервер

Если tg-router уже стоит и работает, и хочешь добавить только bridge-фичу:

```bash
sudo bash tools/claude-telegram-router/install-vscode-live.sh
```

или одной командой без клонирования репо:

```bash
curl -sSL https://raw.githubusercontent.com/SergeyLikholat/cc-multiuser-kit/main/tools/claude-telegram-router/install-vscode-live.sh | sudo VSCODE_LIVE_THREAD_ID=2723 bash
```

Что делает скрипт:
1. Бэкапит `index.js`, `commands.js`, `dispatch.js`, `routing.json` с таймстампом.
2. Кладёт новые `bridge.js`, `transcribe.js`, обновлённые `index.js` / `commands.js` / `dispatch.js`.
3. Добавляет VS Code Live топик в `routing.json` (если задан `VSCODE_LIVE_THREAD_ID`).
4. Рестартует `tg-router.service` и проверяет что он живой.
5. При сбое — автоматический откат на бэкап.
6. Создаёт `rollback-vscode-live.sh <TS>` для ручного отката.

> **Обновление с предыдущей версии bridge.** Если на сервере уже стоял VS Code Live без фичи «новая сессия из TG» — этот же скрипт идемпотентно докатит обновление: он перезапишет все 5 файлов (включая `dispatch.js` с bridged-режимом) и не тронет существующий топик в `routing.json`. Безопасно запускать повторно.

Конкретные шаги по топикам, фильтрам и формату display-name — в коде [`tools/claude-telegram-router/bridge.js`](../tools/claude-telegram-router/bridge.js).

## Конфиденциальность

- **Все сообщения проходят через серверы Telegram** — Telegram их видит. Не пишите боту что-то что не написали бы в обычной TG-переписке.
- **Содержимое отправляется в Anthropic Claude API** — то же что и при использовании веб-чата Claude. См. [политику Anthropic](https://www.anthropic.com/legal/aup).
- **Бэкап сообщений** — бот сам ничего не сохраняет долгосрочно (только короткий буфер для контекста сессии). Если хотите долгосрочную память — установите модуль `claude-mem`.
- **Список чатов где может работать бот** — ограничен `~/.secrets/tg-bot.env` параметром `TELEGRAM_ALLOWED_CHATS`. По умолчанию — только тот chat_id что вы указали при установке. Никто кроме вас не может «открыть бота».

## Troubleshooting

### Бот не отвечает

```bash
# Проверить что сервис запущен
systemctl status tg-router

# Посмотреть логи
journalctl -u tg-router -n 50

# Перезапустить
sudo systemctl restart tg-router
```

### «Conflict: terminated by other getUpdates request»

Значит ещё кто-то запустил поллинг с тем же токеном (например, бот раньше работал на другом сервере, или есть VSCode-вкладка с тем же ботом).

```bash
# Остановите всё
sudo systemctl stop tg-router

# Очистите webhook (на всякий случай)
curl -X POST "https://api.telegram.org/bot$TOKEN/deleteWebhook?drop_pending_updates=true"

# Запустите снова
sudo systemctl start tg-router
```

### Бот видит свои же сообщения и зацикливается

Бывает если включили в `BotFather` privacy off и бот реагирует на свои сообщения. В `/opt/claude-telegram-router/access.js` есть фильтр `ignore_bot_messages: true` — убедитесь что включён.

### «Я хочу разрешить ботом пользоваться кому-то ещё»

В `/root/.secrets/tg-bot.env`:
```bash
TELEGRAM_ALLOWED_CHATS=-1001234567890,-1009876543210
TELEGRAM_ALLOWED_USERS=123456789,987654321
```
И перезапустите: `sudo systemctl restart tg-router`.

⚠️ Бот получит доступ к вашему серверу через Claude. Доверяйте только тем кто имеет право на полный доступ.

### Хочу другой стиль — без бота, через webhook

См. [ADAPT.md](ADAPT.md) → раздел про кастомизацию модулей.

## Удаление модуля

```bash
sudo bash uninstall.sh --module tg-bot
```

- Остановит и удалит сервисы
