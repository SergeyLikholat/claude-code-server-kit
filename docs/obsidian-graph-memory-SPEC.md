# Obsidian Graph Memory — спецификация (метод Карпати)

> Статус: DRAFT для обсуждения. Дата: 2026-06-11.
> Контекст: пункт 4 плана внедрения agentic-практик (AGENTIC_SETUP_AGENT.md).

## Цель

Превратить Obsidian из «просто заметок» в граф знаний, который пишет и читает агент:
- Значимые инсайты из Claude-сессий → atomic notes в Obsidian
- Связи через wiki-links `[[...]]` → Graph View показывает паутину
- Агент пишет (`/note`) и читает (`/recall`)
- Синхронизация на телефон/ПК через существующий Syncthing

## Текущее состояние

| Компонент | Состояние |
|---|---|
| Obsidian vault | Есть, Syncthing-mesh через Koara (телефон + 2 ПК) |
| claude-mem | SQLite+Chroma, semantic search, авто-захват сессий |
| Auto-memory | `/root/.claude/projects/-root/memory/*.md`, правила поведения |
| Связь между ними | НЕТ — три изолированных хранилища |

## Разделение ролей (ключевой принцип)

| Хранилище | Роль | Пишет | Читает |
|---|---|---|---|
| claude-mem | сырой поток, semantic search | observer автоматически | агент (mem-search) |
| Auto-memory | правила поведения агента | агент | агент при старте |
| **Obsidian** | **дистиллированные знания, человекочитаемый граф** | агент по `/note` + владелец | владелец визуально + агент по `/recall` |

Obsidian — слой дистилляции, НЕ дублирование claude-mem. Попадает только то, что прошло фильтр «значимо надолго».

## Структура vault

```
<vault>/agent-memory/
├── INDEX.md            ← карта разделов, точка входа графа
├── projects/           ← по заметке на крупную тему (n8n-stylist, plane-fork, tk-vector)
├── decisions/          ← архитектурные решения с датами (2026-06-vpn-setup)
├── insights/           ← технические открытия (hyperos-app-links, di-oauth-fix)
└── people/             ← роли/контакты (опционально)
```

## Формат atomic note

```markdown
---
created: 2026-06-11
source: claude-session
tags: [android, oauth, hyperos]
---

# HyperOS Small Window ломает OAuth callback

Когда приложение в списке «Управление игровыми приложениями», HyperOS
перехватывает Chrome CCT в плавающее окно → OAuth callback не доставляется.

Фикс: Настройки → Боковые инструменты → Управление игровыми приложениями
→ выключить тумблер приложения.

Связано: [[insights/android-app-links]], [[projects/diablo-immortal]]
```

Правила:
- Одна заметка = одна мысль (atomic)
- Заголовок = суть в одну строку
- Тело ≤ 15 строк
- Минимум 1 wiki-link на связанную заметку (иначе узел повиснет вне графа)

## Команды (skills)

### `/note [тема]`
1. Агент смотрит на текущую сессию, выделяет 1-5 atomic инсайтов
2. Показывает владельцу список «что сохранить» → подтверждение
3. Пишет .md файлы в vault, обновляет INDEX.md, проставляет wiki-links на существующие заметки (ищет по названиям через Glob/Grep)

### `/recall <запрос>`
1. Grep/Glob по vault (имена файлов, заголовки, tags, текст)
2. Возвращает топ-5 релевантных заметок в контекст сессии
3. При необходимости подтягивает связанные через wiki-links (1 уровень)

### Авто-режим (опционально, фаза 2)
SessionEnd hook: если сессия длинная (>50 turns), предложить `/note` автоматически.

## Bridge с claude-mem (фаза 2)

- Еженедельный cron: дистилляция новых significant observations из claude-mem → черновики заметок в `agent-memory/_inbox/` → владелец просматривает в Obsidian и раскладывает
- НЕ автоматический перенос всего — только кандидаты с высокой значимостью

## Что НУЖНО решить с владельцем перед стартом

1. **Путь к vault на сервере** — где лежит синхронизируемая Syncthing-папка? (нужен точный путь)
2. **Имя подпапки** — `agent-memory/` ок, или встроить в существующую структуру vault?
3. **Язык заметок** — русский (как общение) или английский (компактнее)?
4. **Фильтр приватности** — психология/финансы НЕ попадают в Obsidian автоматически (vault синхронизируется на несколько устройств)? Или у vault есть приватная зона?
5. **Объём первичной миграции** — начать с пустого, или сконвертировать существующие memory-файлы (`feedback_*`, `project_*`) в заметки?

## Этапы реализации

| Фаза | Что | Время |
|---|---|---|
| 1 | Создать структуру vault + INDEX.md + skill `/note` + skill `/recall` | ~1 час |
| 2 | Первичная миграция полезных memory-файлов в заметки | ~30 мин |
| 3 | claude-mem дистилляция cron (черновики в _inbox) | ~1 час |
| 4 | SessionEnd hook авто-предложение | ~30 мин |

Фазы 3-4 — опциональные, после того как 1-2 приживутся.
