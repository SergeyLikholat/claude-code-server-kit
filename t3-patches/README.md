# T3 Biz — своя редакция T3 Code

T3 Biz — рабочее место с Claude для бизнес-задач (документы, таблицы, письма, файлы), а не для
программирования. Инструменты разработчика не удалены: они в меню «⋯», пункт «Режим разработчика».

Набор патчей поверх официальных релизов T3 (https://github.com/pingdotgg/t3code) и скрипты,
которые собирают из них версию программы рядом со штатной. План и история решений лежат в
`/root/projects/claude-code-server-kit/plans/2026-09-24-t3-patch-provodnik-sortirovka.md`,
русификация описана в `/root/projects/claude-code-server-kit/plans/2026-09-24-t3-rusifikaciya.md`.

## Android-приложение (`mobile/`, `build-apk.sh`)

Своя сборка официального приложения ставится **рядом** с приложением из магазина: пакет
`com.t3tools.t3code.sergey`, на телефоне называется «T3 Biz» (до 2026-10-04 называлась «T3 Code»),
схема ссылок `t3code://`. С 2026-09-25 это единственное приложение T3, официальное удалено.
К серверу подключается ссылкой сопряжения. Облачных push-уведомлений в своей сборке нет (они идут через Firebase разработчиков).


- Скачать на телефон: в проводнике T3 открыть кабинет «Сервер · Claude», папку `t3-patches/apk/`,
  в меню файла выбрать «Скачать». Ставить поверх прошлой сборки: данные сохраняются (номер сборки растёт сам).
- Ключ подписи: `/root/.config/t3patch/android-release.jks`, пароль рядом в `android-keystore.env`
  (оба в ночном бэкапе). Без ключа следующую сборку поверх не поставить.
- Инструменты: Android SDK `/opt/android-sdk` (платформа 36, NDK 27.1, CMake), JDK 17
  (`/usr/lib/jvm/java-17-openjdk-amd64`), отдельная рабочая копия `/root/.cache/t3-build/src-mobile`.
- `update.sh` собирает APK той же версии сам; если APK не собрался, сервер всё равно ставится.

## Команды

```bash
./status.sh                 # что стоит сейчас, патченая ли, что работает
./update.sh v0.0.43         # собрать патченую версию для тега, тесты, установить, переключить
./rollback.sh               # вернуться на предыдущую версию (например, штатную)
./rollback.sh 0.0.42        # на конкретную
./build.sh v0.0.42 --stock  # собрать без патчей — проверка, что сборка совпадает со штатной
./build.sh v0.0.42 --no-i18n  # с патчами, но на английском (каталог …-s8-en), поставить — install.sh
```

Переключение перезапускает службу T3: **открытые сессии обрываются**, треды и история на месте.

## При выходе новой версии T3

1. `t3 update` — ставит официальную версию. Доработки на время пропадут, это нормально.
2. `./update.sh v<новая>` — патчи накатываются на новую версию. Если какой-то не лёг
   (разработчики изменили то же место), сборка останавливается с именем патча, ничего не
   ставится, работает штатная версия. Конфликт разбирается в `/root/.cache/t3-build/src`,
   исправленный патч выгружается обратно в `patches/`.

## Русификация (`i18n/`)

Интерфейс переводится при сборке, исходники T3 не правятся (кроме одной строки подключения).

- `plugin.mjs` — Babel-плагин: меняет строку на русскую, только если она стоит в позиции надписи
  (текст разметки, `title`/`aria-label`/`placeholder`…, `label`/`description` в объектах) **и** есть
  в словаре. Строки, с которыми код сравнивает значения (`=== "Working"`, `switch`, строки в типах),
  не переводятся.
- `ru.json` — словарь:
  - `strings` — английские строки с русскими переводами; шаблоны `"{0} threads"`, формы числа `{0|тред|треда|тредов}`;
  - `files` — перевод только в одном файле (короткие `m`/`h`, слова, которые в других местах служат ключами);
  - `display` + `labels` — надписи, которые одновременно значения логики (статусы тредов):
    переводятся в момент показа, в коде остаются английскими.
- `extract.mjs <исходники> --report` — каталог строк версии (`catalog.json`) и список
  непереведённых (`untranslated.md`). `update.sh` запускает его сам и печатает число.
- `translate.py` — перевод новых строк пачками через Claude CLI по глоссарию из плана.
- `plugin.test.mjs` — тесты плагина (`node --test`).

После выхода новой версии T3 новые строки видны по-английски, пока их нет в словаре; сборка не падает.
Дополнить: `python3 i18n/translate.py`, проверить `untranslated.md`, пересобрать.

## Как устроено

- `patches/` + `series` — серия `git format-patch`, порядок в `series`.
- `vendor/` — браузерные сборки SheetJS и mammoth (версии в `VERSIONS.txt`, контрольные суммы
  в `SHA256SUMS`). Не зависимости проекта, чтобы патч не трогал `package.json` и lockfile.
- `lib/official_config.py` — публичные облачные настройки (Clerk, relay) берутся из
  установленной официальной версии при каждой сборке. Телеметрия разработчиков не переносится.
- Рабочая копия исходников и Node 26 лежат в `/root/.cache/t3-build/` (одноразовые, не бэкапятся).
- Служба запускает `/root/.local/bin/t3 serve` (override юнита). Это ссылка на
  `/root/.t3/runtime/versions/<версия>/t3`, и версия переключается этой ссылкой.
- Правило минимального следа: новый код в `…/sergey/`, в штатные файлы идут строки подключения
  с пометкой `// t3-patch`.
